# 威脅模型

這份文件的目的是讓你**在用之前**就知道它不防什麼。一個把自己說得比實際安全的工具，
比一個沒有的工具危險。

## 一句話

quietdm 防的是**餘光**，不是**注意力**。

它讓一個沒有在看你螢幕的人，繼續沒有在看你螢幕。對於一個決定要讀你螢幕的人，它一
點用都沒有——訊息是明文，就在那裡。

## 防得了

| 情境 | 為什麼 |
|---|---|
| 有人從你身後走過 | 版面沒有跳動、沒有視窗彈出、沒有通知。餘光抓得到的是動作，不是文字 |
| 同事站在旁邊跟你討論程式碼 | 預設什麼都不顯示。要看訊息得你自己把游標停下來，而那半秒你完全控制 |
| 有人瞄了螢幕一眼 | 那一眼看到的是 git blame 的形狀、lint 提示的形狀、hover 視窗的形狀 |
| 有人突然靠過來 | panic 鍵一按，畫面上所有痕跡消失，並進入靜默 |
| 螢幕分享前 | `:QuietdmSilence` 手動靜默一段時間 |

共同點是：**這些人都沒有在讀你的螢幕。** 他們在做別的事，餘光掃到而已。

## 防不了

以下每一項都是**設計上放棄**的，不是還沒做。

### 認真讀你螢幕的人

訊息內容是明文。使用者要一眼讀懂，內容就必須是明文；能藏的只有形式、時間與版面
（見 [01-covert-model.md](design/01-covert-model.md)）。一個真的在讀那一行字的人會
讀到「晚上要吃什麼」，不會讀到程式碼。

**內容層的編碼隱寫是明確不做的**：把訊息藏進變數名稱，閱讀成本會高到工具失去意義。

### 螢幕錄影與監控軟體

公司的監控軟體錄的是畫面。畫面上有明文，錄影裡就有明文。偽裝對一段可以暫停、放大、
逐格看的錄影完全無效。

**偵測並規避監控軟體是明確不做的。** 那是一場軍備競賽，而且輸掉的代價由你承擔，不
由這個工具承擔。

### 你的機器被人拿去看

daemon 在磁碟上留下三樣東西，都在 `$XDG_STATE_HOME/quietdm/`，權限 `0600`：

| 檔案 | 內容 |
|---|---|
| `state.db` | **訊息明文**、寄件者、時間 |
| `matrix.db` | Olm/Megolm 金鑰、sync 位置 |
| `pickle.key` | 加密 `matrix.db` 的金鑰——**就放在它保護的東西旁邊** |

`0600` 擋的是同一台機器上的其他使用者。它不擋：能用你帳號登入的人、能讀你備份的
人、有 root 的人、拿到未加密磁碟的人。

不想留下記錄就設 `[daemon] store = "memory"`，daemon 一關什麼都不剩——代價是重啟之
後 L2 沒有上下文可以顯示。

`pickle.key` 唯一擋得住的情境是「只有 `matrix.db` 外流」，例如某個備份工具只抓了
資料庫檔。這不是空的價值，但也就只有這樣。

### 對方端

IG 那一側看到的是完全正常的行為：正常的已讀、正常的上線狀態、正常的回覆。這是刻意
的——一個從不已讀的帳號本身就很可疑。

也就是說：**跟你聊天的人知道你在跟他聊天。** 這個工具偽裝的對象是你旁邊的人，不是
對話的另一端。

### 網路層面

自架 homeserver 與 bridge 表示訊息不經過第三方服務。但：

- 你的網路管理員看得到你的機器在跟一台 Matrix 伺服器持續通訊
- 如果 homeserver 在別的地方，那條連線的存在本身是可見的
- bridge 會直接連 Meta 的伺服器；那條連線跟一個正常的 IG client 看起來一樣

**流量分析不在防禦範圍內。** 一個持續的長輪詢連線就是一個持續的長輪詢連線。

### 你所屬組織的規範

這個工具可能違反你所屬組織的規範。它不會幫你判斷，也不會幫你承擔。是否使用、在什麼
場合使用，由你自己決定。

## E2EE 實際保護什麼

Olm/Megolm 保護的是**訊息在 homeserver 上的狀態**。如果你的 homeserver 是自架的，
那大部分是在保護你自己不被自己看到——實際價值在於：

- 你之後把 homeserver 搬到 VPS 上時，那台機器的持有者讀不到內容
- bridge 與 homeserver 之間、client 與 homeserver 之間的中間人讀不到內容

它**不**保護：螢幕上的內容、`state.db` 裡的內容、bridge 到 Meta 那一段（那一段是
Meta 的協定，不是 Matrix 的）。

**quietdm 沒有實作互動式 device 驗證（SAS）**，它的 device 在別的 client 眼中是未驗
證的。實際影響見 [matrix-setup.md](matrix-setup.md#五e2ee-與-device-驗證)。

## 你該擔心的失敗方式

按實際發生機率排序：

1. **你忘記按 panic。** 這是最可能的失敗，而且沒有任何技術手段能修。挑一個不用想就
   按得到的鍵，然後練到變成反射。
2. **你在不該看的時候把游標停下來了。** L1 需要半秒的靜止；開會時你的手比你想的更
   常離開鍵盤。開會前 `:QuietdmSilence`。
3. **你的 filetype 白名單太寬。** 在 markdown 或設定檔上浮出一行 blame 文字，比在
   `.go` 上顯眼得多。
4. **有人真的讀了。** 見上面。這個工具幫不了你。

## 如果這些對你不夠

那你要的不是這個工具。你要的是一支手機。
